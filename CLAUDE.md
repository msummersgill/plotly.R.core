# Objective

- Create a new R package, plotly.core (in the directory and git repo plotly.R.core), wrapping the plotly.js library with similar design principles as the plotly.py package. (See plotly.py/Contributing.md)
- Code Generation should be used to generate R objects, methods, and documentation based on the plotly schema, ensuring long term maintainability
- Codebase should be as minimal as possible, with as few R package and system dependencies as possible
- R functions should ideally be compatible with existing plotly R package to allow (partial) backwards compatibility for most plotting code
- Prioritize performance, using R libraries like data.table to handle tabular data. Use compiled C and C++ functions where performance is improved 
- Plots should be created as HTMLWidgets
- Static image export

# Scope

## In scope

- Follow the spirit of https://github.com/plotly/plotly.py/blob/main/CONTRIBUTING.md
- Structure directories following conventions in plotly.py where it makes sense and doesn't conflict with the required structure of an R package
- Create utilities to update and bundle the latest plotly.js version
- Create a comparable set of utilities as in plotly.py/.codegen to generate R objects corresponding to plotly.js "Graph Objects" and in-line, comprehensive documentation using roxygen2
  - https://plotly.com/python/figure-structure/
  - https://plotly.com/python/creating-and-updating-figures/
  - https://plotly.com/python/renderers/
- R equivalents of plotly.express live in the separate package plotly.express (~/Documents/plotly.R.express, issue #4), which imports plotly.core
- Shiny integration and plotly proxy objects with functionality matching existing R package
- Quarto integration with functionality matching existing R package
- Static image export with headless Chrome (chromote); EPS via rsvg
 
## Out of scope

- Translation from ggplot2 to plotly figures
- Anything described as deprecated in the plotly.R, plotly.js, or plotly.py repos (i.e. deprecated figure_factory)
- Dash Support
- matplotlylib module
- Plotly Studio
- ipywidgets

# Conventions

- Tests are plain base R scripts in `tests/*.R` (use `stopifnot()`), run by `R CMD check`. Do not use testthat or tinytest.
- Generated graph objects follow plotly.py: one constructor per compound schema node, named after its path (e.g. `go_scatter()`, `go_scatter_marker()`, `go_layout_xaxis()`), each with generated roxygen docs. Validator parameters are generated as data (like plotly.py's `_validators.json`) and interpreted by hand-written base validators.
- Generated R files are prefixed `zz-gen-` and committed. Do not edit them by hand.
- `Rscript commands.R updateplotlyjs [version]` updates the bundled plotly.js from npm. `updateplotlyjsdev [path]` uses a local clone.
- Generated docs: one help page per constructor (traces, the layout, every nested object and the shared types), with examples generated by codegen/examples.R.
- Generated constructors and add_*() functions put `...` before the property arguments, so property names must be given in full (R would otherwise partially match e.g. `scen` to `scene`).
- `CODEGEN_SCOPE` in codegen/generate.R is `NULL` (full schema). Set it to a list to limit generation while developing.
- tests/fixtures/ holds reference output from plotly.py, regenerated with the scripts in codegen/fixtures/. Behaviour ported from plotly.py should be tested against such fixtures.
- Plotly Express (`px_*()`) is not part of this package: it is plotly.express (~/Documents/plotly.R.express), which imports plotly.core. Functions it needs from plotly.core are exported under the internal help topic `plotly.core-extending` (R/extending.R): keep their behaviour stable, and check plotly.express when changing them. plotly.py's colour sequences and scales are `plotly_colors` (R/zz-gen-colors.R, from codegen/resources/plotly_colors.py); plotly.express exports them as `px_colors`.
- Examples (roxygen and README) pipe a data frame in and refer to columns with formulas: `mtcars |> go_figure() |> add_scatter(x = ~wt, y = ~mpg)`. Generated examples (codegen/examples.R) use R's own datasets.
- plotly.core doesn't import data.table (codegen uses it). Vignettes may (it is in Suggests).
- A length-1 vector wrapped in `I()` is kept as a JSON array by the serialiser and the validators.
- The legacy plotly R API (plot_ly(), ggplotly(), highlight(), add_sf(), ...) lives in the plotly package (~/Documents/plotly.R, branch plotly-core-render), which builds its figures and converts them with as_go_figure(); plotly.core keeps only what that package needs from the renderer (widget settings, crosstalk linking in the widget JS, Shiny, static image export, last_plot(), TeX()).
- Crosstalk linking: plotly's highlight() sets the widget settings `keys`, `sets`, `frameKeys`, `highlight` and `selectize`; the crosstalk section of inst/htmlwidgets/plotly_core.js (a port of the legacy widget's TraceManager) does the linking, and crosstalk_deps() adds the libraries. selectize.js comes from the crosstalk package; colourpicker is bundled in inst/htmlwidgets/lib/colourpicker (MIT).
- Map views from plotly's map subplots come in the widget setting `fitBounds`, applied in JS with MapLibre's cameraForBounds() and Plotly.relayout(). The image exporter starts Chrome with --allow-file-access-from-files, without which maps don't load in its file:// page.
- Graph-object property values may be one-sided formulas, evaluated by plotly_object() in add_<trace>()'s `data` argument or the data frame given to go_figure() (stored as the figure attribute `plotly_data`, never serialised). One add_<trace>() call is always one trace: no color/split mapping in graph-object functions (that is plotly.express's px_*() and plot_ly()).
- The widget serialiser (widget_to_JSON() in R/widget.R, the htmlwidget's TOJSON_FUNC) sends numeric vectors and matrices in traces and frame traces as base64 typed arrays (`{dtype, bdata, shape}`), like plotly.py's convert_to_base64(): integers, and doubles that are all whole numbers in the int32 range (lossless), narrowed to i1/i2/i4; integers with NA as f8; other doubles f8, or f4 for as_float32() vectors (class `plotly_float32`, kept by validate_coerce() and `[`) or with options(plotly.core.float32 = TRUE); keys geojson/layer/layers/range skipped, length-1 values only when wrapped in I(), unnamed lists not encoded. to_JSON() (plotly_json(), print, save_image(), Shiny proxy) stays plain JSON; prepare_json() writes doubles with C_num_json() (src/json_num.c) in the fewest significant digits that read back exactly (15-17, as JavaScript prints numbers), since jsonlite's digits = NA keeps only 15. Date and date-time vectors in traces are sent as typed arrays of days / wall-clock whole ms in the object's time zone (spec key `rdate`, years 1000-9999 only), plus a `usec` typed array (0-999) when any value has a fraction of a millisecond (date-times keep microsecond precision), and restoreDates() in the JS turns them back into the exact strings format_datetime() writes before plotting (plotly.js reads numbers on date axes in the viewer's time zone, so they can't stay numbers). JS code that works on input traces (crosstalk, legend event data) decodes them with decodeTypedArrays(). In plain JSON, date-time arrays are written as pre-built `json` strings (json_verbatim) to skip jsonlite's string escaping.
- Figure-level widget settings (config, event source, Shiny events, keys, mathjax) are stored as go_figure attributes `plotly_<name>` (p$x$<name> for plot_ly() objects); modify_figure() keeps all attributes.
- Shiny events, proxy calls, crosstalk linking can't run in R CMD check; when changing them, test manually (headless Chrome via chromote). save_image() tests in tests/test-save-image.R run only with NOT_CRAN=true and a browser available.
- Once `src/` exists, NAMESPACE must contain `useDynLib(plotly.core, .registration = TRUE)` before running roxygen. The C init function is `R_init_plotly_core`.
