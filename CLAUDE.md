# Objective

- Create a new R package, plotly.R.core, wrapping the plotly.js library with similar design principles as the plotly.py package. (See plotly.py/Contributing.md)
- Code Generation should be used to generate R objects, methods, and documentation based on the plotly schema, ensuring long term maintainability
- Codebase should be as minimal as possible, with as few R package and system dependencies as possible
- R functions should ideally be compatible with existing plotly R package to allow (partial) backwards compatibility for most plotting code
- Prioritize performance, using R libraries like data.table to handle tabular data. Use compiled C and C++ functions where performance is improved 
- Plots should be created as HTMLWidgets
- Static image export

# Scope

## In scope

- Follow the spirit of https://github.com/plotly/plotly.py/blob/main/CONTRIBUTING.md
- Structure directories following conventions in plotly.py where it makes sense and doesn't conflict with the required structure of an R package
- Create utilities to update and bundle the latest plotly.js version
- Create a comparable set of utilities as in plotly.py/.codegen to generate R objects corresponding to plotly.js "Graph Objects" and in-line, comprehensive documentation using roxygen2
  - https://plotly.com/python/figure-structure/
  - https://plotly.com/python/creating-and-updating-figures/
  - https://plotly.com/python/renderers/
- Create an R equivalents to plotly.express
  - https://plotly.com/python/plotly-express/
- Shiny integration and plotly proxy objects with functionality matching existing R package
- Quarto integration with functionality matching existing R package
- Static image export with the Kaleido package

- Anything described as deprecated in the plotly.R, plotly.js, or plotly.py repos (i.e. deprecated figure_factory)
- Dash Support
- matplotlylib module
- Plotly Studio

# Conventions

- Tests are plain base R scripts in `tests/*.R` (use `stopifnot()`), run by `R CMD check`. Do not use testthat or tinytest.
- Generated graph objects follow plotly.py: one constructor per compound schema node, named after its path (e.g. `go_scatter()`, `go_scatter_marker()`, `go_layout_xaxis()`), each with generated roxygen docs. Validator parameters are generated as data (like plotly.py's `_validators.json`) and interpreted by hand-written base validators.
- Generated R files are prefixed `zz-gen-` and committed. Do not edit them by hand.
- `Rscript commands.R updateplotlyjs [version]` updates the bundled plotly.js from npm. `updateplotlyjsdev [path]` uses a local clone.
- Generated docs are one help page per trace type (go_<trace>(), its nested go_<trace>_*() constructors and add_<trace>()) plus go_layout() and one page per top-level layout object, to keep installed help under CRAN's ~5MB documentation guideline.
- Generated constructors and add_*() functions put `...` before the property arguments, so property names must be given in full (R would otherwise partially match e.g. `scen` to `scene`).
- `CODEGEN_SCOPE` in codegen/generate.R is `NULL` (full schema). Set it to a list to limit generation while developing.
- tests/fixtures/ holds reference output from plotly.py, regenerated with the scripts in codegen/fixtures/. Behaviour ported from plotly.py should be tested against such fixtures.
- Plotly Express is a port of plotly.py's express module: R/express-core.R and R/express-figure.R (core, `_core.py`), R/express.R (the `px_*()` functions, `_chart_types.py`), R/express-doc.R (shared argument docs, `_doc.py`), R/express-trendlines.R, R/express-imshow.R, R/express-data.R. Behaviour must match plotly.py: tests/test-express.R compares 72 cases with fixtures generated by codegen/fixtures/px_fixtures.py (needs plotly, pandas, numpy, statsmodels, pillow).
- Examples (roxygen and README) pipe the data in and refer to columns with formulas: `px_data_tips() |> px_bar(x = ~day, y = ~total_bill, color = ~sex)`, `mtcars |> plot_ly(x = ~wt, y = ~mpg)`. Multi-column px arguments use `~c(a, b)`. Rows are filtered with data.table subsetting: `px_data_gapminder()[continent == "Oceania"] |> px_line(...)`.
- In px code, `args` is an environment (exact `$` matching, NULL values kept like Python's None). Never use `$` on user-supplied or template lists where partial matching could hit another name; use `[[`.
- Tabular data is handled with data.table (as.data.table(), setorderv(), set(), grouping with `by`), not data.frame/rbind/cbind/interaction()/per-group `%in%` scans. Split rows into groups once (row indices per group), not by scanning the data for each group. data.table functions that work by reference (setDT(), setorderv(), set()) must only touch tables the package created: setDT() on a list keeps the list's vectors, which may be the user's columns, so build tables from lists with as.data.table() (which copies).
- Inside data.table's `[`, only a lone variable name is evaluated in the calling scope; any expression in `i` sees column names first. Compute indices first (`o <- order(...); dt[o]`).
- A length-1 vector wrapped in `I()` is kept as a JSON array by the serialiser and the validators.
- Legacy plotly R API compatibility lives in R/compat-*.R (internal helpers prefixed `lp_`), ported from ~/Documents/plotly.R without its banned dependencies. In that code `%||l%` is the legacy package's `%||%` (also falls back for zero-length values). plot_ly() objects are lazy htmlwidgets of class c("plotly_R_core", "plotly", "htmlwidget"); legacy_figure() builds them into validated go_figures. tests/test-compat.R compares with fixtures from codegen/fixtures/legacy_fixtures.R (needs the legacy plotly package).
- Crosstalk linking (highlight(), highlight_key()) lives in R/compat-highlight.R and the crosstalk section of inst/htmlwidgets/plotly_R_core.js (a port of the legacy widget's TraceManager). plot_ly() builds keep `key` and `set` in the traces; legacy_figure() moves them to the widget settings `keys`, `sets` and `frameKeys`, and the JS puts them back on the traces before plotting. selectize.js comes from the crosstalk package; colourpicker is bundled in inst/htmlwidgets/lib/colourpicker (MIT).
- add_sf() (R/compat-sf.R) is ported from the legacy package's own sf code (no ggplot2 code is involved); lp_sf_crs() was written here because the legacy st_cast_crs() came from GPL-licensed leaflet. Map subplots get their initial view from the widget setting `fitBounds`, applied in JS with MapLibre's cameraForBounds() and Plotly.relayout(). Map traces don't render in headless Chrome from file:// pages (the style never loads), so test map views manually in a browser.
- Graph-object property values may be one-sided formulas, evaluated by plotly_object() in add_<trace>()'s `data` argument or the data frame given to go_figure() (stored as the figure attribute `plotly_data`, never serialised). One add_<trace>() call is always one trace: no color/split mapping in graph-object functions (that is px_*() and plot_ly()).
- The widget serialiser (widget_to_JSON() in R/widget.R, the htmlwidget's TOJSON_FUNC) sends numeric vectors and matrices in traces and frame traces as base64 typed arrays (`{dtype, bdata, shape}`), like plotly.py's convert_to_base64(): integers, and doubles that are all whole numbers in the int32 range (lossless), narrowed to i1/i2/i4; integers with NA as f8; other doubles f8, or f4 for as_float32() vectors (class `plotly_float32`, kept by validate_coerce() and `[`) or with options(plotly.R.core.float32 = TRUE); keys geojson/layer/layers/range skipped, length-1 values only when wrapped in I(), unnamed lists not encoded. to_JSON() (plotly_json(), print, Kaleido, Shiny proxy) stays plain JSON. Date and date-time vectors in traces are sent as typed arrays of days / wall-clock ms in the object's time zone (spec key `rdate`, years 1000-9999 only), and restoreDates() in the JS turns them back into the exact strings format_datetime() writes before plotting (plotly.js reads numbers on date axes in the viewer's time zone, so they can't stay numbers). JS code that works on input traces (crosstalk, legend event data) decodes them with decodeTypedArrays(). In plain JSON, date-time arrays are written as pre-built `json` strings (json_verbatim) to skip jsonlite's string escaping.
- Figure-level widget settings (config, event source, Shiny events, keys, mathjax) are stored as go_figure attributes `plotly_<name>` (p$x$<name> for plot_ly() objects); modify_figure() keeps all attributes.
- Shiny events, proxy calls, crosstalk linking and Kaleido export can't run in R CMD check; when changing them, test manually (headless Chrome via chromote for Shiny; reticulate with kaleido 0.2 and >= 1.0).
- Once `src/` exists, NAMESPACE must contain `useDynLib(plotly.R.core, .registration = TRUE)` before running roxygen. The C init function is `R_init_plotly_R_core`.
